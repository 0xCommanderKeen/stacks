# Previewed batch acceptance

Inbox now connects discovery to the catalog. Select individual files across pages, or preview all eligible files in the current search/scan. The default bulk choice includes ready files and byte duplicates; select review candidates explicitly, or choose the Review filter, to include exceptions. Source replacements after a previous acceptance return to Review. Discovery and preview do not create works or write source originals.

Choose register-in-place or managed-copy storage. Both verify original bytes against the preview checksum, preserve source files, and use the same import/recovery journal. Bulk additions default to Archive; assigning a followed run promotes the default into Library. An explicit Keep in Archive or Keep in Library choice remains an override. Existing candidate choices survive unless a batch field deliberately overrides them.

Edit an individual candidate’s title, authors, shelf, designation, or sort position before previewing. Batch metadata can set a shared title, authors, shelf, and an existing series/run. Matching runs are paginated, retaining the chosen run across pages. Choosing a run never creates or merges series by name. Blank designation/position fields use the embedded issue designation where available; bounded decimal or fraction values supply the position. Non-numeric values and numbers outside the catalog’s ±1e9 bounds start at position 0 and stay visible in the preview so annuals and specials can be corrected. Candidate edits are stored separately from raw facts.

Audio recording boundaries require an explicit decision. Select up to 2000 same-source audio tracks to create one recording, then review natural filename order including disc folders. Other publications cannot form a file set. Alternatively, confirm that audio files represent individual recordings. The scanner never assumes that a folder is one audiobook. A track already belonging to a catalog recording resolves to that owner rather than becoming a duplicate work; partially overlapping recording sets must be deliberately regrouped in the catalog.

Preview snapshots each candidate revision, checksum, accepted metadata inputs, and group identity. All-matching previews use SQL insert/select; application memory does not hold the archive’s ID list. Snapshot facts omit page/chapter arrays and covers, retaining only metadata needed for the accepted choices and receipt. Previews are SQL-paged; explicit audio sets have a bounded natural-order preview. Confirmation fails if a candidate revision changed. Source bytes are checked again during execution. A candidate being processed cannot be edited underneath publication.

One existing intake worker executes one acceptance group between scan steps, with acceptance ahead of further background discovery. Jobs and item states remain in SQLite. Cancel stops at a checkpoint; copying and hashing check between chunks and extraction keeps its subprocess timeout. After the publication journal is committed, that publication finishes and its result is recorded even if cancellation arrives. Shutdown joins the worker before closing the database. Temporary storage errors do not permanently kill the executor; durable state can retry when storage becomes usable.

New work metadata, series membership, and personal shelf policy are committed in the same transaction as original ownership. Raw embedded facts remain separate in the import/representation record. A retry after publication but before receipt acknowledgement resolves the existing original owner without multiplying works. Duplicate acceptance never patches a prior owner’s descriptive metadata. Matching bytes can refresh a registered original’s verified modification observation. An earlier pending import with different metadata or storage choices must be recovered before accepting a different preview; it cannot silently supply the new job’s result.

Receipts retain their preview metadata and checksum, while work links follow the accepted representation’s current ownership through grouping/splitting/undo. A later source replacement or candidate edit cannot rewrite the original acceptance decision. Schema0010/export10 and catalog backups include job options, candidate snapshots, groups, and results. Queued acceptance can restore into a fresh library with relocated source aliases. Registered originals still require separate source backups.

Inbox links use the application’s existing work-navigation callback, retaining the persistent audio player. They opt out of SvelteKit’s parallel link handling using its [documented link option](https://svelte.dev/docs/kit/link-options#data-sveltekit-reload); the callback handles ordinary clicks without a page reload. Modified clicks retain normal browser link behavior. A navigation revision guard ignores a work response that arrives after the owner has left its Inbox context.

Verification includes managed/read-only original identity; metadata/raw-fact separation; inherited and overridden shelf policies; explicit run identity and issue order; stale preview and changed source refusals; pending-journal choice conflicts; current byte-duplicate ownership; audio grouping/order; cancellation/restart; interrupted publication/receipt acknowledgement; temporary database failure; queued-job backup restoration with relocated roots; authenticated APIs; and desktop/phone acceptance/reload/Back journeys. NAS throughput, trash, and the remaining release gates stay under their parent issues.
